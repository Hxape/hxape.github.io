# Подготовка выпуска сайта

`build.mjs` собирает браузерные модули Bun и проверяет обязательные HTML. `export-resources.rb` записывает список ресурсов с SHA-256. Обе команды принимают необязательный каталог снимка; ручной запуск не создаёт коммит.

`watch-build.rb` сначала собирает сайт, затем повторяет сборку и обновление списка ресурсов при изменениях `src/**/*.mjs`, `cli/build.mjs` или `public/html/**/*.html`. Запуск из каталога сайта — `ruby cli/watch-build.rb`, остановка — `Ctrl+C`. Ошибка оставляет команду ждать следующую правку; порождённые файлы не запускают повторную сборку.

`post-commit.rb` читает зафиксированный HEAD и создаёт отдельный коммит изменившихся выходов. Он сравнивает пары `data-repository`/`data-url` нынешнего и предыдущего `catalog.html` без оформления, порядка строк и регистра GitHub-имени. Правка только разметки обновляет JS и ресурсы. Изменение состава каталога или политики `site.json` сохраняет нужный экспорт исходных проектов и проверку выбранной ветки; чужая рабочая копия не переключается.

`export-haxelib.rb` готовит индекс и деревья выбранных установок общего `.haxelib`; изменение его входов запускает этот экспорт через hook. `export-repository.rb` готовит один разрешённый снимок проекта. Проверки origin, ветки, HEAD и чужих выходов остаются у экспортёров.

`install-post-commit.rb` устанавливает управляемый hook только в подходящие Git-корни, сохраняя чужие hooks. Явный повтор — `ruby cli/post-commit.rb --retry hxape.github.io` из каталога сайта; он повторяет план зафиксированного коммита, не выбирает другую ветку и не является режимом «только ресурсы».
