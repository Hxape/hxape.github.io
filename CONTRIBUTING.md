# Руководство по разработке проекта

[README](README.md) описывает возможности сайта и границы опубликованных данных. Этот документ нужен для изменения интерфейса и обновления каталога.

## Настройка окружения

Раздайте каталог сайта обычным статическим HTTP-сервером и откройте страницу в браузере. Открытие `index.html` через `file://` не загружает JSON и модули. Для разработки интерфейса нужны браузер и Bun версии не ниже 1.4.2; `jsconfig.json` включает строгую проверку JSDoc в редакторе. Ruby нужен для экспорта данных и Git hook. npm для закреплённых браузерных зависимостей не требуется.

На macOS установите [Bun](https://bun.com/docs/installation) и [Ruby](https://www.ruby-lang.org/en/documentation/installation/#homebrew), затем проверьте доступные версии:

```sh
brew install oven-sh/bun/bun
brew install ruby
bun --version
ruby -v
```

Lit загружается из `vendor` в версии, закреплённой в `index.html`; нужные операции загрузки HTML адаптированы из HTMX 2.0.11 в `src/common/html/` и входят в Bun-выпуск. Обработка Markdown, очистка HTML и другие локальные зависимости находятся там же и входят в выпуск Bun; их происхождение и лицензии указаны в `vendor/SOURCES.md`. Собственные модули собираются командой `bun cli/build.mjs` из каталога сайта.

Установку на главный экран описывает `manifest.json`; значки находятся в `public/icons/`. Ссылка на манифест и значок для iPhone заданы в `index.html`. Установка открывает сайт в отдельном окне, а данные продолжают загружаться через сеть.

## Структура проекта

`index.html` и шесть исходных фрагментов `public/html/` задают каркас страницы; ещё четыре HTML описывают всплывающие экраны и общий поиск; Bun проверяет фрагменты и собирает только JavaScript. `src/app/` запускает и связывает её части, `src/auth/github/` владеет доступом. `src/component/` содержит общие молекулы и организмы интерфейса, `src/bloc/` — их обёртки с предметными данными и бизнес-логикой. `src/common/ui/` содержит общие механизмы отображения, а `src/common/network/` — срок запросов и ограниченный кэш текста. Стили находятся в `public/css/`. `public/js/` содержит выпущенный код, `public/json/` — отдельно читаемые настройки, подготовленные деревья и манифесты выпуска; `cli/` — сборку Bun и Ruby-команды экспорта.

### Принятый договор размещения файлов

`index.html` остаётся корневым исходником со ссылками на действующие адреса ресурсов. Дополнительные HTML-фрагменты редактируются в `public/html/`, а все стили — в `public/css/`. Копий этих файлов в других каталогах нет. Собственные браузерные `.mjs` находятся внутри `src/`; у каждого компонента и блока отдельный каталог с кодом в `index.mjs` и описанием в README. Вспомогательные модули и встраиваемые JSON остаются у своего владельца. `public/js/` содержит только собранные Bun файлы.

JSON, которые Bun встраивает в JS, лежат рядом с использующими их исходными модулями в `src/`. JSON, читаемые браузером отдельно, находятся в `public/json/` без копий по другим путям. Порождённые `build.json`, `resources.json` и деревья репозиториев и библиотек остаются там же, но не считаются редактируемыми исходниками. `manifest.json` и `jsconfig.json` остаются в корне, сторонний JS — в `vendor/`, сборочные команды — в `cli/`. Действующий post-commit по-прежнему строит выпуск из точного HEAD отдельным коммитом; pre-commit не добавляется. Раздел «Архитектура» ниже описывает действующие пути; состав выдаваемых файлов сверяется с `public/json/build.json` и `public/json/resources.json`.

## Архитектура

### Выпуск браузерного кода

Исходники сайта находятся в `src/app/`, `src/auth/`, `src/common/`, `src/component/` и `src/bloc/` с расширением `.mjs`. `cli/build.mjs` создаёт четыре входа в `public/js/`: `theme-boot.mjs` и `bootstrap.mjs` имеют классический формат для обычных `<script>`, `main.mjs` остаётся ES-модулем, а `octocat.mjs` — отдельный классический файл для SharedWorker и запасного DedicatedWorker. Тема выполняется синхронно до CSS; bootstrap с `defer` готовит обработку ошибок до запросов фрагментов, ждёт четыре HTML-фрагмента и основные стили, затем импортирует адрес `main.mjs`, явно заданный в `index.html` через `data-main`. Lit браузер получает отдельно по import map; загрузка фрагментов входит в Bun-выпуск.

Bun строит один разделённый граф от `main.mjs`: общий код не копируется между его частями, а менеджер токенов, просмотр исходника и проверка опубликованных версий библиотек загружаются при первом обращении. Успешно загруженный модуль браузер повторно использует в пределах документа; отдельная вкладка создаёт свой экземпляр. Picture-in-Picture переносит живые узлы и повторно не запускает модули. Строки и настройки редактируются в исходных JSON; Bun может встроить их в выпущенный код. Тексты раннего bootstrap отделены от общего словаря, поскольку классические входы не делят чанки с ES-графом.

`public/json/build.json` перечисляет четыре входа и только файлы текущего JS-выпуска в `outputs`: `bootstrap.mjs`, `main.mjs`, `octocat.mjs`, `releases.mjs`, `shared.mjs`, `source-view.mjs`, `theme-boot.mjs` и `tokens.mjs`. Поле `html` перечисляет десять обязательных исходных HTML-файлов `public/html/`; Bun проверяет их, но не копирует и не фиксирует как свои выходы. Сборщик даёт ленивым частям постоянные имена и удаляет прежние хешированные файлы; открытой до обновления вкладке при несовместимом выпуске может понадобиться перезагрузка. `public/json/resources.json` содержит SHA-256 текущих выходов сборки и файлов HTML, CSS, JSON и внешних зависимостей, которые браузер запрашивает сам; исходные `.mjs` в него не включаются. Воркер не делит файлы с главным графом: сборщик проверяет его зависимости, отсутствие ESM-импортов в готовом файле и отдельное имя выхода. Он готовит JS во временном каталоге и публикует его только после успешной проверки всех входов и разделения поздних модулей.

`cli/watch-build.rb` отслеживает `src/**/*.mjs`, `cli/build.mjs` и `public/html/**/*.html`. В ожидании правки он опрашивает их состояние каждые 200 мс. После короткой паузы для объединения сохранений он последовательно вызывает существующую Bun-сборку и, только при её успехе, экспорт списка ресурсов. Новая правка во время сборки вызывает следующий запуск; ошибка оставляет наблюдение работающим. Выходы `public/js/` не входят в наблюдение. Способ запуска и остановки приведён в [README](README.md#сборка-через-bun).

Три всплывающих экрана имеют отдельную разметку: `public/html/bookmarks.html`, `history.html` и `preferences.html`; `search.html` задаёт общий поиск и его историю. `src/common/html/screen.mjs` читает её по требованию владельца popup и сохраняет успешный результат на срок страницы. Именованные `template` составляют экран и повторяющиеся строки; `${имя}` получает готовое значение или обработчик из соответствующего компонента, без исполнения JavaScript из HTML. Постоянные строки шаблона сохраняют обновление прежних узлов Lit. Panel проверяет выбранную область перед показом позднего ответа; SitePreferences обновляет своё представление, сохраняя прежние значения. Отказ разметки допускает повтор и не останавливает журнал или настройки. Единые преференсы включают тему, размер шрифта, цвета и остальные параметры; отдельная кнопка темы остаётся в верхнем или нижнем размещении. Фокус полей и команд обозначается tooltip без цветной обводки. Подписи цветов размещены вне потока справа внутри HEX-полей; действия сброса стоят в той же строке.

### Компоненты, блоки и атомы стилей

Разделение на атомы, молекулы и организмы — постоянный принцип композиции интерфейса:

- **Атом — CSS-класс с одной обязанностью оформления**, которая может требовать нескольких свойств.
- **Молекула — общий компонент с одной самостоятельной функцией интерфейса.** Например, `font-size-control` показывает действия уменьшения и увеличения текста.
- **Организм — композиция компонентов, образующая завершённую область интерфейса.** Например, `preferences-controls` составляет меню из управления размером текста, значками, цветами и действиями.

Молекулы и организмы находятся в `component`; `bloc` связывает их с данными и бизнес-логикой. Уровень композиции и предметное обогащение описывают разные обязанности. Уровень компонента указывается в его README; он определяется функцией и составом, а не длиной кода или числом потребителей.

Молекулы и организмы в `src/component/` реализуются функциями DOM/Lit и составляются друг из друга. Компонент получает готовые подписи, значения, значки и обработчики действий; он не вычисляет права каталога, не выбирает GitHub-адрес и не читает хранилище настроек или токенов. Например, строка дерева получает имя и приписку, а вкладки показывают переданный выбор и передают намерение переключения блоку.

`src/bloc/` содержит обёртки, которые обогащают эти компоненты данными и бизнес-логикой. Это частичное применение: блок связывает параметры представления с текущими данными и своими действиями. Каталог сохраняет выбор, кэши и ревизию доступа; просмотр — историю, режимы и принятие ответов; настройки — сохранение и применение значений. Компоненты не хранят вторую копию этих данных. Локальное управление геометрией панели и таблиц сохраняет прежние сроки жизни.

У каждой молекулы, организма и блока собственный каталог с `index.mjs` и кратким README. Выделение не зависит от повторного использования. Шесть статических HTML-каркасов остаются в `public/html/`; динамическая разметка находится в функциях компонентов. Действующие Web Components каталога, панели, настроек и индикатора ожидания сохраняют регистрацию и перенос прежних экземпляров.

`public/css/atoms.css` задаёт общие роли дизайн-системы. Предметные CSS уточняют размеры и состояния; комментарий перед атомом называет его действие и задаваемые свойства. Подключение к странице и Shadow DOM, каскад, `hidden`, доступность и параметры описаны в [public/css/README.md](public/css/README.md).

### Страница и владельцы состояния

`index.html` содержит постоянный каркас. Выпущенный `public/js/bootstrap.mjs` получает ранние тексты из исходного `src/app/json/bootstrap-strings.json`, загружает четыре части из `public/html/` через модули `src/common/html/` и запускает `public/js/main.mjs`, когда готовы фрагменты и основные таблицы стилей. До этого дерево скрыто; отказ CSS показывает действие перезагрузки. Готовый фрагмент не загружается второй раз в том же документе. Модули по стабильным URL браузер повторно использует в пределах документа; между вкладками действует обычный HTTP-кэш. Запрос фрагмента ограничен 15 секундами, после отказа его можно повторить. `public/css/atoms.css` задаёт общие роли оформления, `public/css/site.css` отвечает за темы и расположение, `public/css/icons.css` — за общие значки, а `public/css/preferences.css` — за оформление настроек внутри Shadow DOM. Исходный `src/app/main.mjs` создаёт и связывает компоненты; `src/bloc/page/index.mjs` управляет размещением настроек, подсказками, нижним адресом и оконным видом.

`src/bloc/catalog/index.mjs` владеет деревом: выбором строки, раскрытием, загрузкой и кэшем данных, правилами видимости и ссылкой на GitHub. Разделы и строки проектов заданы в `public/html/catalog.html`. Конфигурация приходит из `public/json/site.json`; подготовленные деревья проектов читаются из `public/json/repositories/`, а деревья установленных библиотек — из `public/json/haxelib/`. Каталог ограничивает полученные данные разрешённым уровнем до показа, даже если JSON содержит больше.

Строки дерева не переносятся и не обрезаются. `#project-tree` прокручивается по горизонтали и вертикали; жест в сторону не открывает просмотр удержанием. На телефоне первый сдвиг пальца выбирает ось: вертикаль остаётся родной прокруткой браузера, горизонталь меняет только `scrollLeft`. Если браузер уже сдвинул `scrollTop`, ось фиксируется как вертикальная. После отрыва пальца она остаётся занятой до `scrollend`; в браузере без этого события короткий таймер сбрасывается каждым продолжающимся сдвигом. Корень страницы ограничивает масштабирование. В раскрытых нижних настройках кнопка версии и кнопки настроек, а также кнопка раскрытия имеют область касания `44×44` CSS px.

Абзац под узлом с классом `description` остаётся частью содержимого, а не выбираемой строкой. Дополнительный класс `tree-content` продолжает дерево до этого содержимого: `<p class="description tree-content">...</p>`. Описание репозитория ставится внутри его `<details>` сразу после `<summary>`; подготовленное дерево исходников добавляется после описания. Краткая подпись `<span class="module-brief">...</span>` стоит в `<summary>` после имени, видна у выбранного закрытого репозитория и скрывается при раскрытии. Авторское описание позволяет раскрыть репозиторий с уровнем `0`, сохраняя его дерево исходников закрытым; внутренняя вертикаль описания появляется только при показанных дочерних строках. При загрузке отдельного репозитория, проверке его сохранённого дерева или опубликованной версии библиотеки `<tree-loader>` из `src/component/tree-loader/index.mjs` стоит в `<summary>` перед именем вместо значка репозитория; после ожидания значок возвращается, а ошибка дерева остаётся текстом в `p.description` с повтором. Только общая строка ожидания списка `.haxelib` продолжает вертикаль `│` до появления дочерних строк по `refreshTree`.

Постоянную приписку задают внутри `<details>` репозитория. `data-directory-name="bootstrap"` выбирает все каталоги с таким именем; для конкретного каталога используйте `data-directory-path="component/gameplay"`, для файла — `data-file-path="component/Orchestration.hx"`, для поля класса — `data-symbol-path="component/Orchestration.hx#Orchestration.locator"`. Путь начинается от корня опубликованного дерева (для `template-heaps` — от `src`). Текст элемента `<template>` показывается после имени строки независимо от выбора; приписки соседних строк начинаются в одной колонке. Если для каталога заданы и имя, и путь, побеждает путь. Приписка поддерживает строчные теги `mark`, `b`, `i`, `strong`, `em`, `code`, `small`, `s`, `u` и `a`. Распознанная GitHub-ссылка следует общему режиму переходов; удержание открывает информацию о её цели. Ссылка не выполняет действие родительской строки дерева. Остальные HTTP(S)-ссылки сохраняют внешнее назначение.

`src/bloc/document/index.mjs` владеет текущим просмотром, историей, вкладками, режимом HTML или исходного текста и переносом в PiP. Каталог передаёт ему запрос на просмотр и получает события открытия, выбора документа и закрытия; панель не читает внутреннее состояние дерева. `src/component/panel-resize/index.mjs` владеет шириной и перетаскиванием панели; `src/bloc/document/source-request.mjs` — одним запросом исходника и его отменой. `src/bloc/document/source-view.mjs` при первом обращении загружает оболочку `public/html/source-view.html`, а публичный исходник читает с GitHub. `src/component/document-content/index.mjs` оформляет Markdown, очищает HTML и выводит исходный текст. `src/component/resizable-table/index.mjs` отвечает за ширину столбцов в оформленных документах. При закрытии или смене просмотра поздний ответ загрузки не подменяет открытый документ; ошибка доступной загрузки даёт повтор, а запрет конфигурации показывает закрытые данные.

Открытость настроек истории — временное поле `#historySettingsOpen` этой панели, изначально `false`. Оно сохраняется при повторном показе и переносе в PiP; в Journal и хранилище браузера не записывается. Компонент коллекции получает готовые `controlsOpen` и `toggleControls`, скрывает блок через `hidden` и показывает переключатель вместе с очисткой в шапке. Значения и правила сбора по-прежнему принадлежат Journal.

Ссылки открытого документа в `public/css/site.css` (`.document-html a[href]`) смешивают выбранный акцент с серым цветом `--muted`. Ссылки дерева без наведения остаются серыми со слабым подчёркиванием; наведение и фокус показывают акцент и значок назначения вне потока. Начальная непрозрачность подчёркивания — 15%, параметр `--catalog-link-underline-opacity` описан в README стилей.

`src/bloc/preferences/index.mjs` хранит тему, акцент, цвет заливки `mark`, размер текста, четыре флага значков и время удержания. Один экземпляр настроек размещается в верхней части сайта либо в нижнем блоке на узком экране и в PiP. Тема, акцент и `mark` для каждой темы, размер текста, явный выбор групп значков и время удержания сохраняются в браузере. Начальные флаги значков приходят из `site.json`, а сохранённый выбор имеет приоритет. В Shadow DOM настройки подключают `public/css/preferences.css`: стили остаются с ними при переносе. `src/common/ui/icons.mjs` показывает подтверждённо доступный местный SF-глиф либо встроенный SVG без запроса к CDN. `src/app/picture-in-picture.mjs` переносит существующие элементы в отдельное окно и возвращает их при закрытии. Каталог сохраняет выбор и данные, панель — документ и положение чтения; при отказе браузерного API исходный просмотр остаётся на месте.

`src/bloc/update/index.mjs` при запуске запрашивает SHA последнего коммита `main` и сравнивает его с SHA последней успешной установки из `localStorage`. Совпадение показывает действие ручной проверки (`arrow.down.app`), новая версия — действие загрузки (`arrow.down.app.fill`); после успешной проверки или установки кратко виден `app.badge.checkmark.fill`. Одна кнопка переезжает вместе с настройками между верхней и нижней панелью; компонент сохраняет одно состояние и не запускает параллельных операций. Нижние настройки и настольные подсказки клавиатуры по умолчанию открыты; `src/bloc/page/index.mjs` сохраняет явный выбор для них в разных ключах `localStorage`, а раскрытие ради фокуса не меняет этот выбор. `public/html/footer.html` остаётся одним HTML-фрагментом: кнопка копирования стоит слева от адреса GitHub, а плашка отказа видна при свёрнутых настройках. На мобильном и в PiP раскрытые нижние настройки показывают `version: <7 знаков SHA> © 2026 Yerumaku`; на компьютере эта строка скрыта, а версия с подписью находится в подсказке верхней кнопки обновления при наведении или фокусе.

Загрузка начинается только после действия человека. `cli/export-resources.rb` формирует `public/json/resources.json` с SHA-256 ресурсов оболочки. Компонент сверяет список целевого коммита с опубликованным GitHub Pages, проверяет SHA-256 каждого местного ресурса, очищает CacheStorage и лишь после этого записывает новый SHA и перезагружает страницу. При отказе он оставляет прежний SHA и предлагает повтор; зашифрованные токены и настройки не удаляются.

### Как изменить значок управления

Имена новых SF Symbols сохраняются в таблице целиком, включая точки. `icons.mjs` заменяет точки дефисами только в именах CSS-переменных и одинаково применяет это правило при подготовке кнопки и проверке местного глифа.

Найдите имя действия в `src/common/ui/json/control-icons.json`; `src/common/ui/icons.mjs` создаёт его представление. Поле `code` задаётся читаемой строкой Unicode вида `U+100183`, а подтверждённое имя SF Symbols, например `number`, записано в `symbol`. `null` означает только встроенный SVG. Символ создаётся из кода при отображении; вставлять буквальный глиф в исходник не требуется. Код можно найти по имени в [SF Symbols JSON](https://github.com/qzrzz/SF-Symbols-JSON), доступность местного глифа проверяется по растру. `paths` содержит встроенные контуры [Bootstrap Icons](https://icons.getbootstrap.com/), одиночный `path` — собственный контур. При замене сверяйте `d` и `viewBox`: для Bootstrap используется `0 0 16 16`, для собственных контуров — `0 0 24 24`. `badgePaths` добавляет шестерню поверх папки у кнопки выбора значков дерева. Ключ пробует SF `key.fill` или `key.slash.fill`; при отсутствии конкретного глифа остаётся SVG. Размеры заданы в `public/css/icons.css` и `public/css/preferences.css`; источники и лицензии контуров — в `vendor/SOURCES.md`.

Кнопка токенов выбирает `key-slash` или `key` в `SitePreferences.render()` по `tokenActive`; `src/app/main.mjs` передаёт ей `GithubAccess.active` при событии `change`. При правке обоих состояний проверьте ключ без активного токена и после его выбора, наличие SF-глифа и SVG-замену, три размера текста и мобильную нижнюю панель. Для местной проверки используйте свободный порт, отличный от порта стенда `8765`.

Контуры цветных кнопок окна находятся в `public/html/header.html`, их размеры и показ — в правилах `.traffic` файла `public/css/site.css`. У зелёной кнопки два SVG: `.traffic-expand` и `.traffic-contract`; средний PiP-кружок скрывает минус, когда кнопка недоступна.

`src/bloc/tokens/index.mjs` управляет формой из исходного `public/html/token-manager.html`; модуль загрузки фрагментов загружает её при первом открытии кнопки с ключом. Оформление формы находится в `public/css/tokens.css`. Форма очищает поля после успешного добавления или закрытия. При выборе passkey введённый PAT остаётся в поле до подтверждения ключа доступа. `src/auth/github/passkey.mjs` вызывает WebAuthn через `navigator.credentials.create/get` в окне: воркер не может показать системное подтверждение. `src/auth/github/session-client.mjs` переносит полученные байты PRF в Octocat через `postMessage` с transfer, после чего исходный буфер страницы отсоединён; если создание ключа не вернуло PRF, форма предлагает отдельное подтверждение через `get()` без повторной вставки PAT. При добавлении введённый PAT кратко проходит через страницу.

`src/auth/github/octocat.mjs` после сборки работает как `public/js/octocat.mjs`. `src/auth/github/session-client.mjs` запускает именованный SharedWorker `octocat` по протоколу версии 1 либо запасной DedicatedWorker с тем же протоколом. Версия, имя, адрес выпуска, ключи настроек и сроки операций заданы в `src/auth/github/json/octocat.json`; Bun встраивает этот JSON в клиент и воркер. Соединение проверяет версию до восстановления сеанса. Octocat держит открытый PAT и CryptoKey в замыкании, шифрует PAT и закрытые снимки в прежнем формате, сам добавляет `Authorization` к типизированным GitHub GET и не возвращает секреты странице. `src/auth/github/interceptor.mjs` внутри воркера принимает только операции чтения пользователя, репозитория, коммита и разрешённого содержимого Hxape; произвольные URL, методы и заголовки не принимаются. При добавлении воркер проверяет PAT через `/user`; при открытии сохранённой записи расшифровывает её без выдачи PAT странице. `src/auth/github/access.mjs` подтверждает сохранённый шифртекст, ревизию и намерение активации перед разрешением запросов. Страница через `src/auth/github/vault.mjs` записывает только шифртекст и метаданные в IndexedDB либо, при отсутствии API, в localStorage. Если запись сделана в localStorage, метка хранилища удерживает этот выбор после перезапуска; ошибка работающего IndexedDB не переключает записи в другое место. При удалении токена другие вкладки получают уведомление через BroadcastChannel. Публичные site.json, деревья, HTML, CSS, проверка SHA версии и публичные raw-документы остаются прямыми запросами страницы; воркер принимает только обращения с PAT к GitHub API и операции шифрования. Старый `github-auth-sw.js` снимается при запуске страницы, новый Service Worker не регистрируется.

Код воркера доступен любому посетителю сайта. Замыкание не мешает внедрённому скрипту вызвать разрешённое чтение через клиент страницы и увидеть ответ. Граница не возвращает открытый PAT, CryptoKey или готовый заголовок `Authorization` странице после разблокировки и ограничивает виды сетевых запросов; она не заменяет защиту страницы от XSS.

После публикации версии без Service Worker обновите все ранее открытые вкладки сайта: старый код вкладки продолжает работать до её закрытия или перезагрузки.

Инструкция GitHub и форма добавления лежат в одном `<details>`: без сохранённых токенов он открыт, с токенами при каждом открытии окна свёрнут. При раскрытии список токенов ниже него скрывается, а сообщения остаются над ним. Выбор защиты по умолчанию — passkey; пароль доступен рядом. Кнопки удаления требуют подтверждения; ошибка чтения хранилища показывает имя и сообщение браузера с отдельным повтором. Хранилища `https://hxape.github.io` и `http://localhost` независимы. WebAuthn не сообщает сайту, проверил ли устройство Face ID, Touch ID или код, поэтому кнопка разблокировки использует нейтральный значок ключа.

У формы одна настройка автоматического запуска Octocat и запроса passkey — `github-octocat-auto-restore` в `localStorage`; отсутствие записи означает включённое состояние. Ранее явно сохранённый выбор `github-passkey-on-open` переносится в неё, прежний ключ удаляется. Если открытого сеанса нет, холодный запуск сайта и потеря прежнего воркера обрабатываются одинаково: при наличии сохранённого passkey-токена страница однократно подключает воркер и предлагает ключ доступа. Сначала она проверяет короткий сеанс SharedWorker по случайному ключу из `sessionStorage` и сверяет неизменный шифртекст в хранилище. Живой порт не блокирует PAT по таймеру простоя. При штатном `pagehide` клиент отправляет `release` и даёт 30 секунд на возврат; после аварийного завершения без `release` новый порт не получает прежний PAT. Другая вкладка может удерживать SharedWorker и осиротевший секрет до завершения воркера; физическое стирание строки PAT средой JavaScript не гарантируется. Для DedicatedWorker `sessionStorage` хранит отдельный булев признак прежде активного сеанса, без PAT, ключа или handle; после reload он направляет восстановление через ту же настройку. Ручная блокировка или удаление PAT очищает этот признак и не вызывает немедленного автоматического открытия. Если сохранённый токен защищён паролем, восстановление остаётся ручным. Отмена системного подтверждения также оставляет ручную разблокировку. Запрос passkey не ждёт проверки SHA версии сайта.

Строка `#octocat-status` отдельно от состояния PAT показывает ожидание запуска, подключение или повторное подключение, рабочий SharedWorker либо DedicatedWorker и недоступность. При возврате вкладки клиент проверяет действующий сеанс; статус «подключён» не означает, что PAT открыт, и не гарантирует дальнейшую жизнь воркера. После потери PAT и CryptoKey из завершённого воркера страница не получает их из памяти и не делает запросы с PAT напрямую.

У каждого нового PAT поле `addedAt` записывается внутрь шифртекста и как открытая метка времени в выбранном хранилище, чтобы показывать дату также у заблокированного токена. У прежних записей её нет: интерфейс пишет, что дата неизвестна. Замок стоит справа от имени, поэтому имя не сдвигается при смене состояния; открытый замок активного токена снова его блокирует, сохраняя зашифрованную запись. После успешной разблокировки окно управления закрывается.

В менеджере токенов кнопки, состоящие только из значка, не имеют рамки и заливки; область нажатия у них не меньше `44×44` CSS px. Нейтральная обводка фокуса показывается только у текстовых полей; окно, значки, ссылки, строка раскрытия и переключатель защиты её не получают. Клик по затемнению за окном закрывает его тем же путём, что кнопка закрытия; клик внутри окна не закрывает. Значки сохраняют общее правило сайта: доступный SF-глиф или встроенный SVG Bootstrap того же назначения и размера.

При открытии репозитория каталог сначала читает опубликованный `public/json/repositories/<имя>.json`. Если файла нет, он обращается к закрытому источнику. Если файл есть и токен активен, каталог сначала показывает опубликованное дерево, затем заменяет его закрытым. Закрытый снимок содержит структуру уровня `3`; после подтверждения доступа файл и его объявления могут получить возможность уровня `4`. Полный исходник запрашивается при выборе `SOURCE CODE` либо прямом переходе к строке метода или поля. При потере доступа возвращается публичный уровень. `src/auth/github/access.mjs` сразу отдаёт доступную зашифрованную локальную копию после разблокировки, сверяет `.private/site.sha256` с GitHub и скачивает большой `.private/site.json` только при изменении хэша. Пару хэш/JSON он временно читает на одной ревизии ветки; SHA коммита в снимке и кэше не сохраняется. README и CONTRIBUTING читаются из выбранной ветки. При сетевом отказе сохранённое дерево остаётся помеченным, при подтверждённом отказе доступа каталог убирает закрытые строки. Смена или удаление PAT очищает закрытые строки, текущую информацию и нижнюю ссылку; постоянные адреса истории и закладок остаются, а при открытии заново проверяют доступ; поздние ответы сверяются с ревизией доступа. При короткой перезагрузке вкладка пробует восстановить сеанс живого SharedWorker; после завершения воркера сохранённый шифртекст снова открывается паролем либо passkey без повторной вставки PAT.

`src/common/ui/view-utils.mjs`, `icons.mjs`, `tooltips.mjs` и `motion.mjs` содержат общие функции отображения; `src/common/ui/text.mjs` импортирует видимые строки из `src/common/ui/json/ui-strings.json`. `src/common/network/request-lifetime.mjs` ограничивает время чтения ответов. Векторные значки видов дерева принадлежат `src/bloc/catalog/icons.mjs`, а проверка GitHub Release — `src/bloc/catalog/releases.mjs`. `src/bloc/update/index.mjs` проверяет и устанавливает выпуск отдельно от `src/app/main.mjs`. Форма токенов с passkey загружается при первом открытии или при включённом автоматическом запросе. Контроллер PiP остаётся доступным при действии пользователя. Подготовка JSON вынесена в `cli/`; браузер не читает исходные файлы проектов при построении дерева.

### Договор интерфейса

Каталог выглядит как терминальное дерево, но не исполняет команды и не ведёт журнал. Его корневые группы — `contract`, `architecture`, `.haxelib`, `cli`, `lib`, `feature`, `template`, `game` и `editor`. Репозиторий, каталог, файл и объявление Haxe образуют последовательные уровни; перед именами стоят соединители `├─`, `└─`, `│`, без отдельных стрелок раскрытия. Имена и приписки остаются на одной строке, доступной горизонтальной прокрутке. Нижний блок логотипов и подпись Hxape под деревом не добавляются.

Короткое нажатие переключает ветвь; удержание открывает информацию и подавляет следующий короткий щелчок. Ползунок задаёт общее время удержания от 250 до 500 мс, начально 500 мс; выбор сохраняется в `localStorage`. Движение для прокрутки отменяет удержание. Стрелки и `W/A/S/D` ведут по видимым строкам, `Enter` открывает доступную информацию либо переключает обычный каталог, `E` открывает информацию и при удержании переносит её в PiP. Выделение строки само по себе панель не открывает. Если раскрыть строку нельзя, краткий цветовой отклик и замок появляются сразу справа от имени без сдвига имени и соединителей; пустая ветвь не создаётся. Адрес выбранного узла открывается отдельной ссылкой в нижней панели. Замок стоит справа от ссылки. Для `.haxelib` он скрыт. При выборе репозитория Hxape каталог не более одного раза за работу страницы запрашивает `GET /repos/Hxape/<имя>` через открытый GitHub API без учётных данных и с ограничением времени. Только ответ с `private: false` и совпадающим именем подтверждает публичность и скрывает замок; `404`, ограничение частоты и любой отказ оставляют состояние неизвестным, поэтому действует `private` из `site.json`. Для репозитория, считающегося закрытым, замок открыт после `GithubAccess.confirmed`, после показа `state.data.privateSource` при активном PAT и отсутствии блокировки репозитория либо после события `document-select`, означающего успешное чтение текущего документа или исходника. Сохранённая непроверенная копия тоже считается показанным закрытым деревом; отдельная подпись замка не утверждает, что GitHub уже подтвердил её свежесть. Выбор другого адреса сбрасывает только основание от прочитанного файла; подтверждённый доступ и показанное закрытое дерево остаются основаниями для этого репозитория. Одного активного PAT недостаточно.

Начальная видимость значков репозиториев и каталогов выключена, файлов и объявлений — включена; `site.json` может задать другие начальные значения, а сохранённый выбор человека имеет приоритет. Файлы и объявления используют встроенные векторные Codicons с цветами видов Visual Studio Code, без Unicode emoji; управляющие кнопки используют подтверждённый SF-глиф либо встроенный SVG. Значок репозитория — Git из Bootstrap Icons; его цвет и группа `repositories` не меняются. Системная тема действует без ручного выбора; начальный акцент светлой темы коралловый, тёмной — зелёный. Акцент и серая заливка `mark` выбираются и сбрасываются для каждой темы отдельно. Заливка лежит за текстом без подрезания букв; ссылки и контур их фокуса в приписках остаются серыми. Имена файлов и объявлений заметнее серого HXDoc; отсутствие HXDoc не создаёт надпись `No HXDoc.` или пустой блок. Начальный комментарий файла показывается перед объявлениями без повторения его как HXDoc первого объявления.

Документы используют одну панель с вкладками разрешённых типов и отдельным переключением оформленного HTML и исходного текста. На широком экране панель накладывается справа и меняет ширину перетаскиванием, на узком открывается поверх дерева с действием закрытия. Запрещённый конфигурацией документ показывает состояние закрытых данных без повтора; ошибка чтения разрешённого документа предлагает повтор. На уровне `4` файл, тип и метод или поле используют в той же панели `DOCUMENTATION | SOURCE CODE`. Обычное открытие файла удержанием строки или `Enter` использует закреплённый вид: документацию, исходник либо последний выбранный вид. При незакреплённом `last` действует общий сохранённый выбор на любой ширине; без выбора начальной остаётся документация. `E` в дереве сохраняет прежнее открытие информации и не применяет закрепление; история восстанавливает записанный вид. Явное переключение записывает режим в localStorage под прежним ключом `site-mobile-source-mode`, поэтому выбор действует для следующих файлов и после перезагрузки. Выбор `SOURCE CODE` читает полный `.hx` с GitHub и показывает номера строк, выровненные по правому краю поля номеров. На методе или поле `D` либо стрелка вправо сразу открывает исходник, прокручивает к строке объявления и выделяет её фон, не меняя сохранённый выбор. Внутри открытого просмотра файла физическая `D` выбирает `DOCUMENTATION`, короткое `E` выбирает `SOURCE CODE` и сохраняет общий режим; удержание `E` переносит панель в PiP. Обычное открытие файла в `SOURCE CODE` показывает его с начала без выделения первой строки. Повтор этого действия на уже открытом объявлении снова прокручивает и выделяет строку без нового запроса и записи в историю. Отказ чтения исходника показывает повтор; после успеха повтор не заслоняет код. Смена файла, доступа или окна не позволяет позднему ответу заменить текущий просмотр. Приписки по имени и точному пути, допустимые строчные теги и выравнивание соседних каталогов заданы выше; ссылка внутри приписки открывается отдельно и не выполняет действие строки.

На ширине до 760 px и в PiP любой ширины общий верхний бар скрыт, содержимое занимает доступное окно, а тот же экземпляр настроек находится в раскрываемой нижней панели. Нижний блок и настольные подсказки изначально открыты, явный выбор их открытости сохраняется раздельно; раскрытие для восстановления фокуса этот выбор не меняет. Кнопки раскрытия и открытых настроек имеют область не меньше `44×44` CSS px, копирование адреса — `24×18` CSS px. Плашка отказа обновления и адрес видны и при свёрнутых настройках. Версия и © 2026 Yerumaku в мобильном виде и PiP показаны только в раскрытых нижних настройках; на компьютере они находятся в подсказке верхней кнопки обновления. На телефоне масштабирование страницы жестом отключено; ось прокрутки дерева выбирается первым движением и сохраняется до окончания прокрутки. На компьютере кнопки темы и токена приглушены вне наведения на верхний бар или фокуса. В обоих размещениях кнопка обновления стоит между преференсами и ключом. На компьютере при новой версии она приглушена, без обновления скрыта до наведения или фокуса; в нижнем блоке её область 44×44 CSS px, значок 21 px. На сенсорном экране кнопки видимы постоянно.

### Данные каталога

`public/json/site.json` задаёт настройки по умолчанию и переопределения для отдельных проектов. `branch` выбирает ветку репозитория организации: по умолчанию `main`, для отдельного проекта можно указать другую. `level` определяет состав дерева:

| Уровень | Публикуемая структура |
| --- | --- |
| `0` | Дерево исходников закрыто. |
| `1` | Каталоги. |
| `2` | Каталоги и файлы `.hx`. |
| `3` | Также объявления Haxe и HXDoc. |
| `4` | Та же структура, что на уровне `3`; у файла, типа, метода и поля доступен запрос полного исходника. |

На уровне `4` экспортёр сохраняет ту же структуру и HXDoc, что на уровне `3`; тела файлов в JSON не попадают. Панель читает полный текст с GitHub при выборе `SOURCE CODE` или прямом переходе к объявлению по `D` либо стрелке вправо. Публичные и закрытые тексты раздельно удерживаются только в памяти на ограниченное число файлов, суммарный размер и срок, заданные в `src/common/network/json/source-limits.json`; ошибки и незавершённые запросы не сохраняются. Закрытый кэш принадлежит `src/auth/github/access.mjs` и очищается при смене PAT или подтверждённого снимка. Для закрытого репозитория нужен подтверждённый доступ к исходнику; одного активного PAT недостаточно. Флаги `documents.README`, `CONTRIBUTING`, `AGENTS` и `LICENSE` действуют независимо от `level`. Включённый флаг позволяет добавить существующий документ при следующем экспорте; он не создаёт отсутствующий файл и не обновляет опубликованный JSON. `private` задаёт закрытый замок у ссылки, который открывается после подтверждённого доступа; `icons` задаёт начальную видимость значков. После изменения разрешений данные нужно экспортировать заново. Настройки клиента не защищают уже опубликованный файл.

Для проектов Hxape экспортёр помещает разрешённые документы и дерево в `public/json/repositories/<имя>.json`. Для библиотек `public/json/haxelib/index.json` указывает выбранную установку и её подготовленное дерево; выбранный `.dev` помечен флагом `dev`. Настройки `site.json` требуют `.dev` для `heaps`, `hashlink`, `hlsdl` и `hlopenal`; версия и дерево берутся из его `haxelib.json` и исходников. Для остальных берётся самая новая числовая установка, а `.dev` служит запасным вариантом при её отсутствии. Документы публичных библиотек панель получает отдельно из ветки по умолчанию их репозитория на GitHub при запросе читателя. При открытии библиотеки проверка версии выбирается по `installation.source`: GitHub branch/tag читает `haxelib.json` нужного пакета из ветки или проверяемого тега по `packagePath`, а установка из Haxelib использует датированный `public/json/haxelib/publications.json`. Установка с неизвестным источником не выдаёт кандидата. Равенство, старшая установленная версия и несопоставимый тег не получают акцент; его получает только строго более новая опубликованная версия. Отказ проверки оставляет локальное дерево доступным. Исходник GitHub может относиться к другой ревизии, чем выбранная установка. Запрос к GitHub может завершиться ошибкой или ограничением частоты; панель предлагает повторить загрузку документов.

Закрытый снимок уровня 3 готовит тот же экспортер в каждом закрытом репозитории: `.private/site.json` содержит дерево и HXDoc без ссылки на коммит, `.private/site.sha256` — SHA-256 точных байтов JSON. Документы представлены путями; их текст сайт читает через GitHub из ветки `branch`. Эти файлы не копируются в GitHub Pages. Для чтения нужны личный токен с `Contents: Read-only` и доступ к репозиторию. Ключ доступа требует фактической поддержки WebAuthn PRF браузером и поставщиком ключей; при её отсутствии доступно сохранение под паролем.

## Обновление данных

Из корня организации измените нужную запись в `hxape.github.io/public/json/site.json`. Например, при действующих настройках по умолчанию такой фрагмент разрешает публикацию двух документов без дерева исходников:

```json
{
  "repositories": {
    "example": {
      "branch": "develop",
      "level": 0,
      "documents": {"README": true, "CONTRIBUTING": true}
    }
  }
}
```

Затем подготовьте данные из каталога `src` нужного репозитория:

```sh
ruby hxape.github.io/cli/export-repository.rb template-heaps/src
```

Команда записывает `hxape.github.io/public/json/repositories/<имя>.json` и не меняет исходный проект. Путь к `src` можно заменить. Поле `branch` в примере переопределяет `main`; без него используется `main`. После выключения флага `documents.<тип>` повторный экспорт удаляет текст этого документа из создаваемого JSON. Чтобы изменение появилось на сайте, опубликуйте обновлённый JSON вместе с `public/json/site.json`.

Для закрытого репозитория сначала зафиксируйте исходники в его Git-корне, затем выполните:

```sh
ruby hxape.github.io/cli/export-repository.rb --private <репозиторий>/src
```

Команда требует зафиксированные исходники в ветке `branch`, GitHub origin организации Hxape и подтверждение, что репозиторий закрыт. Для отдельного запуска проверка использует публичный GitHub API и доступный через Git закрытый origin; без настроенного доступа она остановится. Она записывает `.private/site.json` и `.private/site.sha256` в сам репозиторий; опубликуйте их в выбранной закрытой ветке. При последующем изменении исходников повторите экспорт. Отдельный публичный экспорт продолжает подчиняться `public/json/site.json`.

Задача VS Code «Обновить закрытые деревья сайта» вызывает `cli/update-private-trees.rb`. Она сверяет публичные репозитории организации через GitHub, обходит зарегистрированные проекты с `src` и показывает по каждому обновление, отсутствие изменений или причину, по которой осталось прежнее дерево. Ошибки разбора Haxe отмечаются отдельно; один ошибочный проект не прерывает отчёт по остальным. Команда ничего не отправляет на GitHub: готовые файлы нужно проверить и зафиксировать в соответствующих закрытых репозиториях.

Для обновления списка установленных библиотек и их деревьев выполните из корня организации:

```sh
ruby hxape.github.io/cli/export-haxelib.rb
```

Команда использует общий каталог `.haxelib` организации и поле `haxelib` файла `public/json/site.json`: `visible` выбирает библиотеки, `sourceRoot` — корень показываемых файлов, `ignore` исключает пути. Вместе публикуются настройки, `public/json/haxelib/index.json` и соответствующие деревья. Документы и сведения о публикациях в индекс и деревья не копируются. `cli/export-resources.rb` строит `public/json/resources.json` по зафиксированному набору ресурсов: без аргумента в рабочем сайте, с аргументом — только в указанном каталоге снимка.

`public/json/haxelib/index.json` хранит `installation.source` по явной настройке `public/json/site.json`; без неё источник `unknown`, даже у числового каталога. Источник `haxelib` не принимается для `.dev` или Git-копии. `packagePath` хранит путь пакета с `haxelib.json` относительно найденного Git-корня, а без него повторяет `documentsPath`; `root` остаётся корнем показываемых исходников. Для GitHub-установки записываются `refKind`, `ref` и точный `sha`: четыре обязательных `.dev` сверяются с веткой и SHA активного манифеста `cli-haxe`; обычная установка из ветки требует совпадения `origin/<ref>` и HEAD с настроенным SHA, из тега — совпадения тега и HEAD с ним.

Отдельная команда `ruby cli/refresh-haxelib-publications.rb` ищет кандидатные номера среди тегов GitHub, затем подтверждает каждый по точной странице `lib.haxe.org/p/<имя>/<версия>/`; неподтверждённый Haxelib номер может остаться лишь кандидатом `[GitHub]` после проверки `haxelib.json` пакета в теге. Она записывает датированный `public/json/haxelib/publications.json` для следующего выпуска сайта и не входит в обязательный post-commit. Сейчас `libraries` в этом снимке пуст: до успешного сетевого обновления публикации не проверены. Сетевой отказ сохраняет прежнее достоверное сведение либо состояние `unknown`; он не означает отсутствия выпуска Haxelib и не блокирует post-commit.

Для ручного выпуска из каталога сайта выполните `bun cli/build.mjs`, затем `ruby cli/export-resources.rb`. Локальный обработчик установите из корня организации командой `ruby hxape.github.io/cli/install-post-commit.rb`: она не заменяет чужие hooks. Установленный `post-commit` берёт зафиксированный снимок HEAD, запускает Bun, формирует список ресурсов и создаёт отдельный коммит только для изменившихся выходов и JSON. Hook не отправляет коммиты на GitHub; исходный коммит остаётся даже при отказе сборки. После устранения причины повторите из корня организации `ruby hxape.github.io/cli/post-commit.rb --retry hxape.github.io`. Переписывание истории пропускается; для ручного `reset` с последующим объединяющим коммитом используйте одноразовый `HXAPE_SITE_EXPORT=skip`. Перед публикацией проверьте, что фиксация выпуска включена.

## Состояние и проверка изменений

Реализованы дерево проектов, отдельные разрешения документов, обзор структуры Haxe и HXDoc, чтение публичных документов библиотек, настройки оформления и перенос в Picture-in-Picture при поддержке браузера. Добавлены локальное управление PAT, чтение закрытого снимка напрямую с GitHub и пакетный экспорт. Подготовлены местные пары `.private/site.json`/`.private/site.sha256`; чтение через GitHub зависит от их публикации в закрытых репозиториях. Проход с действительным PAT и passkey после удаления Service Worker ещё не подтверждён. Полные тексты `.hx` не экспортируются. Интеграционные сценарии уровня `4` и ленивого просмотра пройдены; в настоящем браузере подтверждены публичный исходник библиотеки, строка, закрепление вида и `E`.

После изменения данных проверьте соответствующий JSON и страницу: разрешённый документ открывается, закрытый не содержит текста в опубликованном файле, выбранный уровень показывает только нужные узлы. После изменения интерфейса проверьте затронутые действия мышью и клавиатурой, узкий экран и восстановление просмотра после закрытия панели. В описании изменения укажите, что проверено и какие файлы данных нужно опубликовать вместе с кодом.

## Состояние переходов, истории и закладок

Обмен JSON остаётся у прежних владельцев. Journal выдаёт `version: 1` и различимые `type: bookmark-group`, `bookmark-groups` либо `history`; переносимые записи содержат только `target`, `title`, `reading`. Одна группа хранится в `group` с `name` и `bookmarks`, все группы — в `groups`. Местные id создаются при импорте; группы сопоставляются по точному имени, закладки — по каноническому адресу. Замена одной группы сохраняет остальные, замена всех меняет весь состав. История передаёт `history`, индекс `cursor` либо `null` и `searchQueries`. Panel проверяет адресный блок и запросы через Journal и SearchState до их синхронного принятия; Journal заменяет адресную историю, SearchState объединяет запросы при прежнем пределе 50.

Черновик JSON, режим действия строки и подтверждения принадлежат Panel на срок временной области. Представление коллекции показывает поле для копирования или вставки, выбор объединения/замены и ошибки. Отложенное удаление закладки остаётся у Panel: запись сохраняется до истечения 3 секунд, повторное нажатие отменяет ожидание; закрытие области и освобождение окна снимают таймеры. Удаление группы проходит отдельное подтверждение, Journal защищает последнюю группу. Ожидание удаления истории сохраняет прежние 4 секунды.

Входящий снимок закладок должен содержать уникальные имена групп и уникальные канонические адреса: повторы внутри снимка отвергаются целиком. Форма отклоняет неверный вид или версию, повреждённые метаданные и JSON больше 5 МиБ, сохраняя черновик и прежние данные. Нынешняя закладка совпадающего адреса при объединении сохраняет свою группу. Отказ браузерного хранения показывается отдельно; принятие данных в памяти не объявляется подтверждением их сохранения.

Задание и уточнения записаны в [TASK-NAVIGATION.md](TASK-NAVIGATION.md); договор пользователя описан в [README](README.md#переходы-история-и-закладки). Замечания Astra Max исправлены: текущий отказ Contents отзывает закрытый снимок и текст, ожидание default_branch входит в отменяемый переход, готовый исходник не пересоздаётся при смене строки, смена шрифта обновляет геометрию без нового срока подсветки. Общая фиксация связывает показ, выбор дерева, нижний адрес и запись перехода; поздний ответ не заменяет более новый просмотр. Настройки владеют общим режимом ссылок и местным корнем организации. Компоненты `navigation-actions`, `history`, `bookmarks`, `navigation-collection` и `search` получают готовые записи и действия, не читают права или PAT.

История группируется по файлам; её шапка управляет сбором всех переходов, последовательным объединением (начальный режим), уникальными файлами, учётом смены вида и пределом: по умолчанию 50, до 500. Выключение останавливает новые записи и сохраняет прежние, очистка остаётся отдельным доступным действием. Закладки имеют именованные группы с перестановкой внутри группы. Эти правила и метаданные остаются у Journal/Panel, а компоненты получают готовые значения и действия. Ручная кнопка файла и автоматическое исключение репозитория занимают одно место после стрелок, сохраняя разные действия. navigation-journal проверяет начальный merge, all/unique, учёт вида, предел 50, ручное добавление/удаление с отменой и запрет/разрешение будущих переходов репозитория. Браузер подтвердил ручные настройки и доступность очистки; проверка этих сочетаний не означает перебор всех возможных режимов.

Haxe-файл закрепляет документацию, исходник либо последний выбранный вид обычного открытия. Настройка применяется к Hold/Enter; вкладки и V выбирают текущий вид, E сохраняет свою команду. Поиск файла встроен между toolbar и body; последняя строка и отдельная история запросов сохраняются, выделение и рисунок остаются временными. Независимый разбор выбрал пассивный `search-state.mjs` для строк, MRU 50 и отказов хранения. Panel читает его единственную `latest` и фиксирует завершённое действие Enter/перехода к совпадению/закрытия, без обрывков медленного ввода. Проекция переводит native Range в UTF-16 границы с внутренним округлением; matcher сохраняет границы блоков. navigation-search проверяет ввод и обход истории запросов, выключение сбора, Text/Element и границы от предка, внутреннее округление пробела, пустую/чужую область, обновление и смену вида. source-navigation проверяет сохранение области на готовом Text при фокусе и переходе строки; navigation-access — снятие при отзыве. Закрепление, Hold/Enter/E и восстановление вида истории проверены navigation-links и прежним source-mode-preference. История запросов не подменяется адресами материала; H/N и список запросов не очищают открытую полосу.

Последние уточнения добавляют промежуточный выбор репозитория до ожидания загрузки. Каталог хранит незавершённое намерение глубокого перехода; смена фокуса или доступа отменяет поздний прыжок. Это состояние не входит в журнал просмотров. Готовый файл принимает прежняя панель; ссылка без строки использует сохранённый вид, явная строка выбирает исходный код.

Поиск файла принадлежит Panel, поиск каталога — CatalogSearch у ProjectCatalog. Каждый создаёт свой SearchState из `src/common/search/state.mjs`: прежний ключ файла `site-search-state`, отдельный ключ каталога `site-catalog-search-state`. Общий компонент не читает хранилище и не вычисляет совпадения. Каталог сопоставляет подписи уже загруженных строк, включая свёрнутые; запрос не начинает сетевых загрузок. ProjectCatalog применяет отдельный режим none/temporary/always из Preferences к предкам выбранного совпадения, отслеживая временные раскрытия отдельно от истории. Ручное управление снимает временную принадлежность. История каждого поиска выгружает `{version:1,queries:[...]}`; проверенный импорт объединяет MRU, не меняя latest и сбор. Старшая адресная история продолжает выгружать запросы файла.

Внутренние функции поиска строят проекцию показанного текста и компактный индекс буквальных совпадений без учёта регистра; рисунок вне потока обозначает только текущий диапазон. Материал не оборачивается в новые элементы, единый текст исходника сохраняется. Закрытие материала, его смена и отзыв доступа освобождают проекцию, карту узлов, диапазон и рисунок; успешное обновление и смена вида перестраивают открытый поиск. Перенос PiP пересоздаёт рисунок для фактического документа. В постоянные записи эти данные не попадают; latest и завершённые запросы сохраняются отдельно. Ready-переход к строке того же Text/root/ref/окна сохраняет проекцию и границы выделения.

Удаление истории ожидает 4 секунды в панели; до принятия журнал сохраняет запись. Отмена и состояние ожидания не сохраняются после перезагрузки. Начатый переход использует только метаданные записи: если она удалялась, успешное открытие добавляет её в конец без усечения остальных записей; обычный выбор меняет лишь курсор. Краткие сообщения переходов используют отменяемый таймер фактического окна. Сворачивание меню панели не подключено; молекула раскрытия сохранена отдельно для будущего применения.

В столбце номеров закладка перемещается по строкам и удаляется уводом в сторону; повторное нажатие сохраняет метку. Жест меняет адрес у прежнего владельца Journal, не создаёт вторую закладку на занятой строке и не исполняет завершающий клик. Представление увеличивает область захвата созданной метки и подсвечивает одну текущую строку. На запись списка остаётся одна кнопка удаления. Срез проверен взаимодействиями добавления, перемещения и удаления. В истории отдельное действие добавляет и удаляет закладку повторным нажатием; обычный цвет и контур/заливка показывают состояние, акцентный зачёркнутый знак при наведении — удаление.

Жест закладки начинается после смещения на половину высоты строки. Временная форма поиска вне готового файла допускает захват за поля: порог 15 CSS px, только вертикальный сдвиг без сохранения в браузере. Встроенная полоса файла занимает свою строку модуля информации. Служебные подписи и значки не выделяются, поле запроса остаётся редактируемым. Перенос PiP и очистка временной области прекращают жесты и освобождают их события.

Удержание режима ссылок открывает представление существующей настройки корня организации; Preferences сохраняет владение значением, проверкой и записью в браузер. Нижний адрес VS Code не подменяется GitHub на мобильном устройстве; наличие установленного приложения не проверяется. Все действия удержания получают сигнал готовности перед отпусканием. Заголовок допускает две строки имени без Installed-версии. Эти уточнения реализованы и прошли полный набор перед фиксацией и Astra Max.

На мобильном экране режим ссылок показан только в нижних настройках. Поиск и закладки в нижнем размещении скрыты, пока их верхняя группа доступна в открытой информации; после закрытия документа они снова видны. Узлы и обработчики сохраняются. Режим страницы отражается в `data-*` на `html`; CSS-селекторы применяют условия видимости, в том числе через наследуемые параметры для Shadow DOM настроек. Отдельное состояние режима ссылок для мобильного вида не создаётся.

Дополнительная кнопка PiP из шапки информации удалена. Жёлто-оранжевая кнопка окна и клавиатурные действия используют прежний контроллер переноса.

Последняя проверка выявила два недочёта до фиксации: повтор подготовочного отказа терялся до создания просмотра, а новый модальный документ перекрывал уже открытые закладки при сужении окна. Panel исправляет их у прежнего владельца. PendingRetry хранит только проверенный адрес и параметры следующей попытки; текст, загрузчик, сигнал и доказательство доступа не сохраняются, ActiveView и история не принимают неуспех. При смене размещения прежний popup возвращается после документа в нативный верхний слой с теми же данными, фокусом и прокруткой. Срез проверен полным набором; нативный порядок слоёв дополнительно подтверждён в браузере.

Новое уточнение после полного набора добавляет срок гашения строки. Preferences сохраняет дискретный выбор 0–3 секунды с шагом 0.5 либо ∞; начальный срок 3 секунды. Молекула в меню цветов получает готовое значение и обработчик, текущий таймер остаётся у владельца исходника. Он не меняет адрес или Journal и учитывает смену строки, закрытие, отзыв доступа и перенос окна. Срез реализован и проверен сроками, устаревшим таймером, жестами и переносом окна; обозначения используют проверенные SF `number` и `infinity` с SVG-заменами.

Последняя настройка истории добавляет три режима дерева. Выбор none/temporary/always принадлежит Preferences и сохраняется в браузере; начальный режим temporary. Catalog хранит только временную открытость и отличает ветви, открытые историей, от ранее открытых пользователем. Panel передаёт признак restore истории в прежнюю фиксацию; обычные ссылки и закладки не используют эту настройку. Срез выполнен и проверен переходами по истории во всех трёх режимах.

Принцип компонентов и блоков сохранён: молекулы и организмы состоят из DOM/Lit-представлений, предметные обёртки остаются в `bloc`. Новые поля используют атом `.field`, текстовые действия — `.control` с параметрами оформления, значки — `.icon-button`, цвета и поверхности — общие классы атомов. Параметр `--control-border` сохраняет прежнюю рамку по умолчанию и позволяет задать нейтральное действие. `navigation.css` и `source.css` уточняют геометрию и состояния, включая абсолютные метки закладок, без копирования общего оформления поля или кнопки.

Постоянная история содержит проверенные адреса и метаданные, а не DOM, тексты или загрузчики. Отзыв доступа уничтожает закрытое содержимое и временные запросы; разрешённые пользователем имена и пути остаются. Повторное открытие заново разрешает адрес через каталог. Исходный Markdown-якорь сохраняется отдельно от изолированного DOM-id оформленного документа.

Успешный публичный Markdown временно хранит `src/bloc/catalog/public-document.mjs`, закрытый — `GithubAccess`. Общая проверка пути находится в `src/common/network/document-path.mjs`. Адресное закрытое чтение требует подтверждённого свежего снимка того же репозитория/ref и проверяет доступ до и после ответа. Octocat выполняет разрешённый GET, сохраняя нынешнее право токена на чтение содержимого. Обновление обходит кэш, но отказ не стирает прежний успешный материал. Обновление документа в прежней группе перечитывает разрешённый набор её документов, сохраняя выбранную вкладку и место чтения; исчезновение выбранного документа не подменяет его другой вкладкой.

Для местного VS Code используется пустой по умолчанию корень организации из настроек. Экспорт `.haxelib` добавляет `localPath` — относительное местное расположение выбранной установки или Git-корня. У `.dev` сохраняется логический путь, включая `.hlc/current`, вместо пути конкретной машинной установки. Абсолютный путь пользователя не включается в опубликованные данные. Неоднозначный адрес ветки с `/` требует известной ветки; первый сегмент не считается доказанной веткой.

Проверка исходного среза охватывает переход в незагруженный репозиторий, Markdown и HXDoc → строка, возврат/повтор при отказе, изменение доступа, постоянные записи после перезагрузки, перетаскивание и удаление, горячие клавиши вне полей ввода, узкий экран и перенос/возврат PiP. ## Сборка и проверки

Сайт не собирает Haxe или HL/C. Браузер получает HTML, CSS и выпущенные Bun модули из `public/js/`. Ruby-команды обновления данных приведены выше; интеграционные проверки сайта находятся в `../coverage/hxape.github.io/`.

## Стандарты кода

JS-модули используют JSDoc и строгие настройки `jsconfig.json`; редактор читает наследующий их `tsconfig.json`. Список входов проверки содержит `.mjs`, а используемые `.d.mts` подключаются по ссылкам на типы: при включении обоих соседних файлов в один шаблон TypeScript может выбрать декларацию вместо реализации. Заголовок модуля называет его обязанность; JSDoc экспортируемых и неочевидных функций описывает действие, значимые входы, результат и отказ. В многострочном JSDoc описание и каждый тег стоят на отдельных строках. Комментарии поясняют условия, сроки жизни и порядок действий, которые нельзя понять из самого кода. Внешние JSON, сообщения и записи хранилища проверяются как `unknown` до использования; `any` не заменяет проверку. Крупный компонент делят по самостоятельным обязанностям, сохраняя владельца состояния и публичный договор.

Тип не заменяет описание: поля и свойства `@typedef` объясняют, какие данные хранятся, их назначение и значимые сроки жизни; методы, параметры и результаты описывают действие, смысл входов, выход и отказ. Перед ревью проверяются все собственные `.mjs` проекта, включая неизменённые части. Короткое описание должно помогать восстановить договор по коду, а не повторять имя или тип.

Редактируемые `.mjs` пишут обычные строковые литералы в одинарных кавычках, шаблонные строки — для подстановок; JSON требует двойных кавычек. Для `src/**/*.mjs`, `src/**/*.d.mts` и `cli/**/*.mjs` действует `dprint.json`: браузерные `.mjs` оформляет плагин Prettier 0.72.0, декларации и CLI — TypeScript 0.96.1. Prettier распознаёт встроенные `html`-шаблоны Lit: начало с новой строки, вложенные элементы с отступами и один атрибут на строку. `htmlWhitespaceSensitivity: ignore` нормализует служебные пробелы между тегами и сохраняет обычные границы тегов; содержимое `pre` остаётся предформатированным. Из каталога сайта `bunx dprint@0.58.0 check` проверяет оформление, а `bunx dprint@0.58.0 fmt` применяет его; после команды можно указать отдельный файл. Файлы `public/js/` генерирует Bun и вручную не правят; они и сторонние файлы не входят в форматирование. Владелец каждого запроса отвечает за проверку ответа и повтор; общая функция ограничивает срок ожидания. Постоянные стили хранятся в CSS, включая таблицу стилей Shadow DOM настроек.

В VS Code официальное расширение `dprint.dprint` использует CLI `dprint` из PATH и ближайший `dprint.json`. Настройки JavaScript и TypeScript в корневом `.vscode/settings.json` организации выбирают это расширение и включают форматирование при сохранении. Редактор и команды используют один набор правил проекта.

Длинные строки HTML разрешены общим договором организации. Встроенные `html`-шаблоны Lit форматируются многострочно по прямому поручению, с сохранением осмысленных переносов и пробелов текста, в том числе в терминальных схемах. Статичные `index.html`, фрагменты и HTML документов сохраняют авторское оформление. Сборка выпуска не запускает форматтер.
