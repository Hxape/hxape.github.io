# Стили сайта

Стили образуют дизайн-систему: общие роли оформления задаются классами-атомами, а стили компонентов определяют их размеры, расположение и особые состояния. Атом — одна обязанность, для которой может требоваться несколько CSS-свойств. Например, кнопке со значком нужны центрирование, снятие рамки и заливки, а не отдельный класс для каждого свойства.

Атомы оформляют молекулы и организмы: молекула реализует одну самостоятельную функцию интерфейса, организм составляет компоненты в завершённую область. Их обязанности и разделение `component`/`bloc` определены в [архитектуре проекта](../../CONTRIBUTING.md#компоненты-блоки-и-атомы-стилей).

## Атомы и роли

[atoms.css](atoms.css) содержит общие классы. Перед каждым атомом комментарий объясняет его назначение и свойства, которые получает компонент.

| Классы | Обязанность |
| --- | --- |
| `primary`, `strong`, `muted` | Основной, усиленный и приглушённый цвет текста. |
| `surface`, `bar` | Фон содержимого и фон панели управления. |
| `icon-button` | Общее оформление кнопки со значком. |
| `control`, `field` | Оформление текстового действия и текстового поля. |
| `popover` | Размещение и оформление всплывающего меню. |
| `control-row`, `label-row`, `form-stack` | Строка действий, строка подписи и последовательность полей формы. |
| `plain-list` | Список без маркеров и стандартных отступов. |
| `nonselectable` | Служебное содержимое без выделения указателем. |
| `text-display` | Содержимое области чтения с выделением и копированием текста. |
| `sr-only` | Доступная подпись, скрытая от зрячего пользователя. |

Цветовые роли используют параметры темы: `primary` — `--text`, `strong` — `--strong`, `muted` — `--muted`. Фоны используют `--surface` и `--bar`. Значения темы определяет [site.css](site.css); при смене темы атомы получают новые значения через эти переменные.

Компонент сочетает нужные роли с собственным классом:

```html
<button type="button" class="control primary document-retry">Повторить</button>
```

Здесь `control` оформляет действие, `primary` выбирает цвет текста, а `document-retry` задаёт особенности кнопки повтора. Выделение CSS-атомов не требует объединять компоненты с похожим видом.

## Каскад и параметры компонента

Общие свойства принадлежат атому. Собственное правило компонента уточняет геометрию, состояние или параметр атома, сохраняя одну общую декларацию свойства:

```css
.document-retry {
  --control-padding: 7px 12px;
  --control-radius: 7px;
  --control-background: var(--bar);
}
```

`control` применяет эти параметры к отступам, скруглению и заливке. Таблица атомов подключается раньше стилей компонентов, поэтому последующее правило той же специфичности может переопределить её значения. CSS-переменные наследуются; отдельный контекст сам по себе не возникает. Значение на самом элементе, включая исходное значение в классе-атоме, имеет приоритет над унаследованным значением. Параметры уточняются на элементе компонента.

Параметр `--control-border` задаёт рамку текстового действия; по умолчанию это `1px solid var(--line)`. Действия без рамки и заливки задают `--control-border: 0` и `--control-background: transparent`, сохраняя общие свойства атома `control`.

## Скрытие и доступность

В обычном документе служебный интерфейс получает `user-select: none` на `html`; настройки повторяют это правило на своём ShadowRoot-хосте. Атом `text-display` явно разрешает выделение в содержимом документов и исходников. Поля `input`, `textarea` и редактируемые области сохраняют выделение значения; команды, вкладки и значки, включая текст SF-глифа внутри SVG, не выделяются. Правила `user-select` и `-webkit-user-select` не меняют нажатия, фокус или `hidden`. Различия наследования браузеров учитываются явными исключениями; [описание свойства](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/user-select) объясняет значение `auto` у потомков.

Атомы, задающие `display`, используют условие `:where(:not([hidden]))`. Оно не добавляет специфичности: вес селектора остаётся весом самого класса. На элементе с `hidden` такой атом не задаёт раскладку и не отменяет штатное скрытие. Особые состояния компонента по-прежнему могут иметь собственные селекторы.

`sr-only` сохраняет подпись в документе, размещая её в обрезанной области размером 1×1 пиксель. Для такой подписи нельзя использовать `hidden` или `display: none`, если она должна оставаться доступной вспомогательным средствам. `plain-list` снимает оформление списка и сохраняет его HTML-структуру. Классы оформления не заменяют доступные имена, роли, состояние кнопок и управление клавиатурой.

## Подключение и границы файлов

`index.html` подключает `atoms.css` перед `site.css` как обязательную таблицу стилей. Запуск интерфейса ждёт её вместе со стилями страницы и значков. [preferences.css](preferences.css) импортирует те же атомы внутрь Shadow DOM настроек: стили основного документа через эту границу не проходят. Picture-in-Picture получает таблицы стилей исходного окна и переносит прежние узлы интерфейса.

`site.css` хранит тему и особенности страницы, дерева и просмотра. `preferences.css`, [tokens.css](tokens.css), [source.css](source.css) и [table-resize.css](table-resize.css) уточняют соответствующие части интерфейса; [icons.css](icons.css) задаёт отображение значков, [no-script.css](no-script.css) — сообщение без JavaScript. Это исходные файлы, которые браузер читает непосредственно. Список ресурсов и их контрольные суммы обновляет `cli/export-resources.rb`.

`source.css` загружается при первом просмотре исходника. Цвет состояния `source-state` остаётся в этой таблице: после её загрузки сообщение приглушено, а при отказе загрузки сохраняет унаследованный цвет. Постоянный атом `muted` на таком состоянии изменил бы аварийный вид, поэтому здесь важен срок применения стиля, а не только совпадение значения цвета.

Поле `source-highlight-control` в меню цветов использует атомы `form-stack`, `control-row` и `field`. Дискретное положение range и срок готовит Preferences; CSS только размещает поле и output. Для бесконечности output показывает SF `infinity` либо встроенный SVG, сохраняя доступный текст «не гасить». Размер этого знака — `16px`, он не зависит от увеличения текста.

## Ссылки каталога

`--catalog-link-underline-opacity` в `:root` файла `site.css` задаёт видимость подчёркивания без наведения: начально `15%`, допустимый ручной диапазон — от `0%` до `100%`. При наведении или клавиатурном фокусе известная ссылка получает полный акцент и рисунок своей цели: репозитория, каталога, файла по расширению либо строки кода.

Пустой `span.navigation-link-icon` расположен слева вне потока и скрыт от вспомогательных средств; текст не сдвигается. Его `::before` получает маску, а тень применяется к внешнему span, чтобы маска не обрезала ореол. `--catalog-link-icon-shadow` задаёт смещения, размытие и цвет для `drop-shadow`: начально `0 0 2px var(--surface)`. Неприсвоенная маска использует прозрачное SVG и не создаёт цветной квадрат.

## Поле поиска

`navigation.css` оформляет `form[role="search"]`: счётчик расположен справа от input, лупа — в отдельной левой ячейке общей рамки. Поле использует общий стиль преференсов и занимает остаток ширины; все действия находятся справа в той же строке. Значки действий имеют размер 24px. Обводка фокуса снята, tooltip показывает сфокусированное действие или поле. Полоса каталога ограничена видимой шириной дерева рядом с документом.

Явная кнопка `delete.left` очищает поле и удаляет этот запрос из истории; нативный cancel скрыт CSS, поскольку не предоставляет отдельной команды истории. Поле остаётся `type=search` с обычным редактированием; User-Agent и проверка установленного приложения не используются. `#docs-search-bar` занимает отдельную строку между toolbar и телом документа. Скрытая полоса не занимает высоту.

`--search-drag-y` смещает только popup по вертикали; горизонтальная позиция сохраняет центр CSS. Поверхности жеста — счётчик, левая область лупы и прозрачные поля формы `--search-inset`; их `touch-action: none` не является свойством предка input. Встроенная полоса не получает края для перемещения. Ввод и кнопки не начинают жест, служебные подписи не выделяются. Срок жеста и снятие смещения принадлежат компоненту переноса и Panel.

## Верхние действия просмотра

Закрытие занимает левую колонку на всю высоту верхней панели. Справа имя занимает до двух строк; сразу под ним стоят назад/вперёд, обновление и вид. Сетка имеет естественную высоту и не оставляет пустой строки под коротким именем. Правые действия центрированы по высоте поверх подложки имени, слева направо: режим ссылок, закладки, поиск. Нижняя строка резервирует ширину правых кнопок, поэтому они не перехватывают её нажатия.

`--docs-control-shadow` у `.docs-header` задаёт ореол рисунков цветом `--bar`. Компактные действия используют области `44×44 px`; закрытие сохраняет полную высоту панели. При точном указателе на широком экране правые действия видны при наведении или фокусе шапки. В компактном виде все действия видны постоянно.

Верхние общие копии Search/Bookmarks/LinkMode получают `--site-navigation-opacity` и `--site-navigation-events` от `html[data-header-pointer-over="true"]` либо `html[data-header-focus-visible="true"]`. Обычный фокус после нажатия указателем не удерживает их открытыми; touch не получает этих ограничений. PageAppearance отражает признаки по нынешнему верхнему бару и видимому клавиатурному фокусу.

Нижнее меню прокручивается по горизонтали внутри доступной ширины, чтобы условные повтор и PiP оставались достижимыми. Раскрытие и таймер скрытия к шапке не подключены; отдельная молекула раскрытия сохранена для будущего использования.

В компактном размещении `--icon-size` верхней строки равен `21px`, как в нижних настройках; закрытие сохраняет `22px`. Для закрытия используются отдельные рисунки `<` и `>`, выбранные шириной окна, без дополнительного поворота.

PageAppearance отражает нынешнее размещение в `html[data-preferences-placement="footer"]`: режим ссылок скрыт в шапке и доступен в нижних настройках. `html[data-information-open="true"]` того же окна скрывает только нижние закладки и поиск через наследуемый `--footer-journal-display`. Без открытой информации они возвращаются; узлы и обработчики сохраняются. Верхние настольные действия остаются. `data-hold-ready` окрашивает цель по достижении порога; снятие готовности и действие после отпускания принадлежат владельцу жеста.

Фон направляющих summary, native leaf и description начинается в `content-box`, как текстовый префикс. Это значение сохраняется после сокращённых свойств фона; подсветка готовности меняет только `background-color`, поэтому не сбрасывает рисунок и его начало.

## Детали закладок

Только подготовленное `.navigation-detail.has-icons` показывает репозиторий и относительный путь двумя частями со значками. `--navigation-detail-icon-size` начально равен `12px`; промежуток значка и текста — `4px`, между частями — `8px`. Цвета видов сохраняются, общие отступы исходных SVG снимаются. Имя сущности остаётся выше; доступная подпись перехода содержит вид, а декоративные знаки скрыты от вспомогательного чтения.

Удаление имеет область `44×44px` с отрицательным вертикальным отступом `4px`: её внешнее место остаётся `36px`, поэтому новая область касания не увеличивает высоту строки. Служебные подписи не выделяются. История использует те же готовые значки репозитория и вида, а физические файлы показаны раскрываемыми группами с копией отдельного знака файла.

Подсказки работают при наличии наведения независимо от ширины основного окна или PiP. Готовую подпись берут из `data-tooltip` либо `aria-label` кнопки со значком. В открытом dialog подсказка помещается в тот же контекст, поэтому её не отделяет модальная инертность внешнего body.

Поля сбора истории и именованных групп закладок используют атомы `field`, `control-row` и `form-stack`; компонент уточняет только отступы и размеры. При выключенном сборе дополнительные поля скрыты через `hidden`, а очистка сохраняет своё место. Кнопки сохранения и сброса каталога используют общий `icon-button`: 28px в верхних настройках, 44px с рисунком 21px в нижних настройках и popup.

Кнопка закрепления вида показывает Doc либо Code с маленьким pin вне потока; последний выбранный вид обозначает pin.slash. Геометрия кнопки не меняется: badge 9px на широком экране и 11px в компактном. Source-вкладки сохраняют выбранную заливку без дополнительной рамки фокуса после горячей клавиши.
