# Задание: переходы, история и закладки сайта

Поручение пользователя от 2026-10-01. Имена репозиториев игр и редакторов на сайте скрыты умышленно; сохранять эти обозначения. Стиль терминала/исходного кода сохраняется для работы рядом с редактором в PiP.

## Требуемый результат

1. В документации файла каждое объявление становится ссылкой на свою строку исходника. Нажатие переключает `DOCUMENTATION` на `SOURCE CODE`, загружает файл при необходимости, прокручивает и выделяет строку.
2. Ссылки GitHub в описаниях дерева, включая схему `architecture/modules`, разбираются по назначению. Ссылка на известный репозиторий выделяется акцентом при наведении; знак перехода слева расположен вне потока и не сдвигает текст. Нажатие сразу выбирает репозиторий, раскрывает его и всех предков и показывает загрузку при необходимости. Для глубокой цели сохраняется незавершённое намерение: после загрузки и при сохранённом фокусе репозитория выполняется переход к узлу, раскрытие пути и просмотр файла. Уход фокуса отменяет поздний прыжок. Файл без строки использует последний выбранный вид, явная строка открывает `SOURCE CODE`. Уже раскрытые ветви не сворачиваются.
3. Markdown-ссылки на доступный документ, файл или объявление открываются внутри сайта. При переходе в другой репозиторий его данные загружаются по необходимости. Успешно прочитанный Markdown кэшируется; кнопка обновления явно перечитывает материал с GitHub.
4. Общий режим ссылок циклически переключается между внутренним переходом, VS Code и GitHub. Кнопка показывает соответствующий знак: SF Pro `number` со встроенной заменой Bootstrap, VS Code либо GitHub. Ссылки Haxelib не выдаются за адреса исходников GitHub.
5. Отдельная история просмотров сайта заменяет запись просмотров в историю браузера. Кнопки назад/вперёд, обновления и вида стоят под именем материала; режим ссылок входит в правую группу верхней панели.
6. `Z` — назад; `X` — вперёд; `C` — обновить текущий материал; `V` — переключить `DOCUMENTATION/SOURCE CODE` либо `TEXT/HTML`; `B` — переключить режим ссылок.
7. `H` или удержание стрелок назад/вперёд открывают историю в popup/боковой панели. Отдельная кнопка истории не нужна. Выбор записи только устанавливает курсор истории, не меняя её порядок. Корзина справа запускает удаление без подтверждения, с отменой в течение 4 секунд; запись остаётся видимой и доступной. Успешное открытие записи во время удаления добавляет её в конец и перемещает туда курсор. Список сохраняет закладки и перестановку перетаскиванием.
8. Нажатие на номер строки исходника добавляет закладку; повторное нажатие её не удаляет. Закладку можно перемещать вдоль столбца номеров, пропуская занятые другой закладкой строки. Перетаскивание влево или вправо за столбец удаляет закладку. У созданной метки увеличена невидимая область захвата над строкой и под ней. Подсвечивается только текущая строка жеста. Закладки представляются списком и деревом; `V` переключает эти представления в панели закладок. Панель показывает репозиторий и вид материала: метод, поле, класс, файл, каталог с собственным README либо Markdown-документ. В строке списка одна кнопка удаления; текст не выделяется при взаимодействии мышью или пальцем, рамка не появляется от такого фокуса. Переход загружает отсутствующий материал.
9. `<` и `>` — предыдущая и следующая закладки; `/` — открыть последнюю открытую или созданную закладку; `Shift+/` — удалить текущую закладку, чей адрес совпадает с адресом нижней панели; `N` — открыть панель закладок.
10. `F` либо `M` открывает поиск с фокусом поля. В открытом файле компактная полоса встроена между toolbar и body; счётчик справа от поля, закрытие у правого края. Шесть действий: очистить текущий запрос из поля и истории, предыдущий/следующий результат, искать в выделении файла, собирать историю запросов, закрыть. В поле вверх/вниз выбирают историю запросов, на кнопках — совпадения. Последняя строка и отдельная история завершённых запросов сохраняются в браузере; удержание кнопки поиска открывает список запросов с удалением. Вне готового файла остаётся временная форма поиска.
11. Реализовать и встроить компоненты; в README описывать договор возможностей, в CONTRIBUTING — устройство и действительное состояние реализации. Уточнения сохранять в этом файле по мере работы.
12. После окончания реализации и проверок провести независимое ревью через Astra с рассуждением Max. Пользователь уточнил цель: найти и доработать недочёты готовой реализации, рассматривая поведение, устройство и связанные участки целиком. Разность файлов служит вспомогательным материалом. Подтверждённые замечания устранить и проверить перед итоговым отчётом.
13. Вернуть закрытие информации чевроном слева: `<` на узком экране и в тонком PiP, `>` в широком виде. Появление — короткий прилёт справа, закрытие — улёт вправо. Закрытие занимает всю высоту у левого края. Справа от него имя материала выше, под ним управляющий блок: история назад/вперёд, обновление, вид. От правого края в порядке справа налево: поиск, закладки, режим ссылок. Левые элементы не накладываются друг на друга, наложение правых действий на подложку допустимо. Сворачивание меню и его чевроны удалены из панели; компонент раскрытия сохранён для будущего использования. Значки репозитория и каталога показаны как у файлов и сущностей. Кнопки имеют подсказки и размытую тень цвета фона; в мобильном виде их размер соответствует нижней панели. Настольный вид с мышью показывает часть действий при наведении/фокусе. Ошибка перехода скрывается через 3 секунды.
14. Настройка истории выбирает поведение дерева: не раскрывать; раскрывать временно и сворачивать открытые историей ветви при уходе с записи; раскрывать с сохранением открытости. Временный режим показывает текущий материал в дереве. Настройка сохраняется в браузере; пользователь выбрал временное раскрытие по умолчанию.
15. Удержание кнопки режима ссылок открывает ввод местного пути организации с сохранением и сбросом. Пустой путь по-прежнему выключает VS Code. В режиме VS Code нижняя ссылка сохраняет адрес `vscode://…` и на мобильном устройстве: его можно передать через буфер. Наличие установленного редактора не определяется браузером и не является условием построения этой ссылки.
16. Каждый элемент с удержанием визуально сообщает о достижении порога. Действие выполняется после отпускания; отменённый жест не открывает панель. В имени материала допускаются две строки; подпись `Installed {version}` из этой области удалена, версия остаётся доступной в других местах.

Изображения пользователя уточняют расположение элементов панели и действия ссылок; написанный пользователем запрос определяет задание.

## Уточнения

- Скрытые имена игр и редакторов — намеренная граница публикации, а не ошибка каталога. Предложение об их согласовании с раскрытием предметных имён отозвано.
- `COURCE CODE` в перечислении горячих клавиш означает существующий режим `SOURCE CODE`.
- Горячие клавиши действуют в окне сайта или PiP и не перехватывают ввод в полях. `V` действует по открытому представлению: файл, документ либо список/дерево закладок.
- Ответ пользователя: режим VS Code открывает установленный редактор.
- Ответ пользователя: история и все закладки сохраняются в этом браузере после перезагрузки, включая имена, пути и строки закрытых материалов; тексты файлов в записи не входят.
- Ответ пользователя: в настройках добавить путь к каталогу организации. По умолчанию путь пуст; пока он не заполнен, ссылки VS Code не включаются. Настройка остаётся местной.
- Ответ пользователя: `.haxelib` и все репозитории подразумеваются в корне организации. Местные адреса вычисляются относительно заданного корня; отдельный корень для библиотек не вводится.
- Выбранные пользователем SF-глифы: назад `arrow.backward`, вперёд `arrow.forward`, обновление файла `arrow.down.document`, история `list.bullet.rectangle`, закладки `bookmark`, поиск `magnifyingglass`. `bookmark.fill` обозначает добавленную закладку и показывается рядом с номером строки кода; `bookmark.slash.fill` удаляет закладку.
- Виды закладок используют Codicons: [дерево list-tree.svg](https://github.com/microsoft/vscode-codicons/blob/main/src/icons/list-tree.svg), [список list-flat.svg](https://github.com/microsoft/vscode-codicons/blob/main/src/icons/list-flat.svg).
- Для замка закрытого файла пользователь выбрал [Codicons lock-small.svg](https://github.com/microsoft/vscode-codicons/blob/main/src/icons/lock-small.svg). Для файла, открытого с PAT, используется открытый вариант того же рисунка. Критерии подтверждённого доступа сохраняются.
- Снимок пользователя со строкой `ReplaceStream` уточняет размещение: знак закладки стоит перед номером строки вне потока HTML; колонка номеров имеет фиксированную ширину, чтобы знаки разных строк не смещались по горизонтали.
- Пользователь подтвердил требуемый принцип оформления: `component / bloc` соответствуют молекулам/организмам и обёрткам с предметной логикой, общие классы стилей являются атомами. Новые поля и действия используют `.field` и `.control`; собственные классы задают геометрию и состояния представлений.

Проверить собственные `.mjs` сайта, включая существующий `PageAppearance`, и дополнить описания назначением, владением, сроком жизни, значением входов/выходов и отказом там, где это существенно.

При наведении слово выделяется акцентом; значок слева определяется назначением GitHub-пути: репозиторий, каталог/README, файл либо строка файла. Один общий знак перехода для всех путей не используется.
- Нажатие с удержанием ссылки в дереве открывает информацию о цели ссылки. Используется общее настроенное время удержания; последующий короткий клик подавляется, действие родительской строки не выполняется.

Поиск охватывает текущий документ и исходный код, показывает текущий номер/число совпадений и позволяет перемещаться стрелками. Внешний крестик удаляется; сброс внутри поля остаётся браузерным, с собственной заменой при отсутствии. Лупа слева не является кнопкой.

Состояние ожидания не сохраняется, перезагрузка или окончательное отключение отменяют ещё не принятое удаление. При успешном открытии удаляемой записи захваченные метаданные позволяют добавить её в конец даже после истечения таймера; отмена удаления возвращает обычный переход без перестановки. Неуспешная загрузка запись не восстанавливает.

- При поэтапном переходе из узкой панели каталог становится видимым сразу. Ошибка или отмена не возвращает автоматически прежнюю панель, фокус и нижний адрес: выбранный репозиторий и повтор загрузки остаются перед пользователем. Прежний принятый материал и место чтения сохраняются у панели и в истории. Отказ `C` внутри уже показанного материала по-прежнему сохраняет его показ и адрес.

Перемещение по номерам не допускает двух закладок на одной строке; занятые строки пропускаются. После перетаскивания завершающий клик не выполняет другое действие. - Перед запуском Astra Max закончить доработки и проверки, затем зафиксировать изменения в Git; ревью ищет ошибки, недоработки и несоответствия договору в зафиксированном состоянии. Исправления по ревью проверяются и фиксируются отдельно.

Пользователь обнаружил, что закладки на узком экране исчезают и возвращаются при расширении.
- Отказ подготовки материала не создаёт успешный просмотр или запись истории. Панель сохраняет только местные метаданные для явного повтора `R`: адрес и параметры перехода, без текста, доказательства доступа, загрузчика или сигнала. Новый переход заново проверяет доступ. При прежнем успехе его тело, имя, курсор и нижний адрес сохраняются; без него показана оболочка с повтором. Сообщение ошибки скрывается через 3 секунды. Новый адрес, закрытие и отзыв доступа очищают попытку; удалённая запись истории не восстанавливается повтором.
- Последнее оформление относится только к меню закладок: перед именем репозитория показывается стандартный значок репозитория либо ветки для источника из ветки. Вид сущности/файла обозначается соответствующим значком слева от относительного пути вместо слов Class/Field/Method/File. Имя сущности остаётся в верхней строке; доступная подпись сохраняет вид материала.
- В меню выбора цветов добавить дискретный слайдер времени гашения подсветки строки после изменения её адреса/закладки. Пользователь выбрал 0, 0.5, 1, 1.5, 2, 2.5, 3 секунды и ∞; по умолчанию 3 секунды. Максимум — не гасить, обозначен SF `infinity`. Гашение меняет только визуальную подсветку, не ссылку, строку, историю или закладку. Настройка хранится в браузере.
- «Через сколько гасить» означает срок показа: фон сохраняется до выбранного момента, затем снимается. Это задержка перед снятием, не постепенное уменьшение яркости на протяжении всех 3 секунд. При 0 фон сразу скрыт, при ∞ не запускается таймер.
- Горизонтальная полоса прокрутки исходника не закрывает последнюю строку. Выбран простой постоянный нижний отступ у текста и столбца номеров, не зависящий от завершающего перевода строки; фиктивная строка и новый номер не добавляются.
- Последний глиф кнопки Open in this site — SF Pro `number` (решётка), он заменяет прежний signpost.right.and.left.fill во всех копиях кнопки. Встроенная SVG-замена сохраняется.
- Пользователь допустил замену доработанного текущего воркера и уточнил: сейчас пользователь один, для обновления достаточно закрыть страницы сайта и открыть снова; версионирование и дополнительный код не нужны. `protocol: 1`, имя `octocat`, формат хранения сохраняются; расширен вид существующей команды `content` (`linked-document`). Дополнительные проверки возможностей, новые имена и переходные слои не вводятся.
- Переходы `<`/`>` между закладками одного готового файла сохраняют живой текст и оболочку без очистки, лоадера и мигания. После проверки доступа меняются строка, подпись, адрес, история и место чтения. Смена файла/ref/доступа и явное обновление проходят полную подготовку.
- Выделение текста разрешено только в содержимом `SOURCE CODE`, `DOCUMENTATION` и других областей чтения. Служебные элементы, включая значки, вкладки, шапки и подписи дерева, не выделяются. Поля ввода сохраняют обычное редактирование и выделение значения.
- В истории кнопка закладки переключает добавление и удаление повторным нажатием. Без закладки показан контур `bookmark`, с закладкой — `bookmark.fill`, оба обычного приглушённого цвета. При наведении используется акцент, а имеющаяся закладка показывает `bookmark.slash.fill` для удаления. История и её порядок при этом не меняются; правило столбца номеров остаётся отдельным.
- История имеет сгруппированный по файлам вид. В шапке виджета выбираются: хранить историю; собирать все переходы внутри файлов, объединять последовательные переходы одного файла (по умолчанию) либо хранить только уникальные файлы; учитывать смену вида (по умолчанию нет); предел элементов (по умолчанию 50, до 500). Каждый новый вход в файл сохраняет своё последнее положение чтения, а в уникальном режиме оно принадлежит единственной записи файла. Включённый учёт смены вида подчиняется выбранному объединению.
- Выключение хранения сохраняет накопленные записи и останавливает новые переходы. Настройки способа сбора, смены вида и предела скрыты; кнопка полной очистки видна всегда и неактивна только при пустой истории.
- Закладки получают именованные пользовательские группы. Перестановка разрешена только внутри текущей группы; группы и принадлежность сохраняются в браузере.
- В истории оформление репозитория и относительного пути повторяет правило закладок: значки репозитория/ветки и вида материала вместо текстового указания File/Class/Field/Method. Доступная подпись вида сохраняется.
- Коды SF-глифов записываются в прежней таблице читаемыми строками `U+HEX`, например `U+100183`, рядом с подтверждённым именем символа. Буквальный глиф создаётся только при отображении; кодовые точки, проверка местного шрифта и SVG-замены сохраняются.
- Настройка называется «Автоматически собирать историю». Выключение не скрывает стрелки виджета информации. После назад/вперёд и перед обновлением стоит отдельная SF `plus/minus` в ручном режиме: принудительно добавить текущий файл либо удалить его из истории, в том числе после возврата назад. В автоматическом режиме это место получает отдельное действие репозитория, описанное ниже. Стрелки не подменяются; закладки и материал не меняются, окно отмены сохраняется. Удержание стрелки открывает настройки и при пустом списке.
- В автоматическом режиме место ручных plus/minus занимает plus.diamond/minus.diamond: разрешить или запретить последующий сбор текущего репозитория. Пользователь подтвердил разные действия по режиму. Прежние записи сохраняются, внутри истории есть список запрещённых репозиториев с возможностью снять запрет.
- Кнопка Haxe-файла меняет политику обычного открытия, а не текущую вкладку: всегда DOCUMENTATION, всегда SOURCE CODE либо последний выбранный вид с pin.slash. Удержание и Enter учитывают закрепление; явная строка/право и E сохраняют поведение. Пользователь подтвердил: E в дереве открывает информацию как прежде, E внутри панели выбирает исходник. История восстанавливает сохранённый вид. Вкладки и V переключают текущий материал; для Markdown кнопка HTML/текст сохраняется.
- После E вкладки документации/исходника не получают лишнюю акцентную рамку и оформление фокуса. Выбранный вид остаётся обозначен обычной заливкой; поля ввода и строка кода сохраняют свои отдельные состояния.
- F открывает поиск, M остаётся дополнительной клавишей. В открытом файле компактная полоса встроена между document-toolbar и docs-body; счётчик справа от поля, закрытие у правого края. Введённая строка хранится в браузере и переносится между файлами; история запросов отдельна от истории материалов, открывается удержанием кнопки поиска и допускает удаление.
- В поле поиска вверх/вниз выбирают историю запросов; при фокусе на кнопках панели — найденные совпадения. Шесть действий: очистить текущий запрос из поля и истории (delete.left), предыдущее/следующее совпадение, поиск в выделении файла, сбор истории (circle.badge.plus включён / circle.badge.minus выключен, по умолчанию включён), закрытие. Диапазон выделения не переносится на другой файл и не сохраняется.
- Части медленно набираемого слова не записываются как отдельные запросы. Фиксируется завершённое действие Enter/переход к совпадению/закрытие поиска; результаты при вводе обновляются сразу. Поле сохраняет текущую строку и при выключенном сборе истории, прежние запросы остаются.
- В форме местного пути Organization directory сохранение и сброс показаны кнопками без текста: externaldrive.badge.checkmark и externaldrive.badge.xmark (последняя поправка пользователя). Доступные названия и подсказки сохраняются; меняется только путь в настройках браузера.

## Границы реализации

- Сохраняются прежние владельцы состояния. `DocumentPanel` владеет одним живым просмотром и внутренним журналом адресной истории/закладок. `ProjectCatalog` разрешает адреса, знает нынешние снимки/права, выбирает строку и ведёт нижний адрес. `GithubAccess` хранит закрытые тексты; настройки хранят общий режим ссылок и путь организации.
- Постоянная запись содержит только проверенный адрес, подпись, вид материала, выбранное представление и место чтения. DOM, загрузчики, тексты, PAT и доказательства доступа не сохраняются. Адрес повторно разрешается при открытии записи.
- Новый адрес материала содержит источник (вид, ключ каталога, GitHub URL), вид назначения, а для файла — полный путь относительно Git-корня и отдельный `ref`. Для объявления добавляются путь объявления и строка; для Markdown — исходный якорь. Сгенерированный DOM-id якоря не сохраняется.
- Catalog предоставляет `prepareTarget(target, {signal, refresh})`, `targetIsCurrent(prepared)`, `acceptTarget(prepared, shownTarget)`, `revealRepository(origin)`, чтение текущего адреса нижней панели и преобразование ссылки по выбранному режиму. Panel предоставляет `navigate(target, {visit, refresh})`, обновление и переключение нынешнего вида. Новый общий владелец текущего просмотра не вводится.
- После ожиданий Panel проверяет действительность операции, принимает материал, Catalog принимает выбор/нижний адрес, внутренний журнал принимает переход. Старый ответ не меняет новый просмотр. Отзыв доступа очищает закрытый текст и временные запросы, сохраняя разрешённые пользователем записи истории и закладок.
- Кэш Markdown содержит только успешно прочитанный текст. Публичный кэш остаётся у публичного загрузчика, закрытый — у `GithubAccess`. Явное обновление обходит кэш; отказ обновления не уничтожает прежний успешный материал.
- Упомянутый Markdown не ограничивается четырьмя вкладками. Закрытое адресное чтение требует подтверждённого свежего снимка того же репозитория/ref, проверенного пути Markdown/README/LICENSE и проверки доступа до и после запроса. Запрос выполняет Octocat в пределах прежнего `Contents: Read-only`.
- Для `.haxelib` экспорт добавляет относительное местное расположение выбранной установки/Git-корня. Абсолютный путь организации остаётся в браузере. Имена скрытых игр/редакторов не восстанавливаются из местных каталогов.
- Начальный режим ссылок внутренний. Пустой местный корень исключает VS Code из переключения; GitHub и внутренний режим остаются доступны. Относительные Markdown-ссылки разрешаются от текущего репозитория/ref/документа. Неоднозначный `ref` с `/` не подменяется догадкой.
- H/N открывают представления журнала, не создавая запись просмотра сами по себе. `V` переключает список/дерево закладок, когда открыта эта панель; иначе переключает вид нынешнего материала. Поиск F/M работает с показанным материалом и не загружает репозитории или файлы ради поиска. Частный SearchState хранит latest и MRU завершённых запросов; Panel владеет действиями, временной проекцией, областью выделения и рисунком.
- Переход на другой документ остаётся переходом материала. Смену представления SOURCE/HTML либо DOCUMENTATION/SOURCE CODE учитывает отдельная настройка, по умолчанию нет; при включении действует выбранный способ объединения файла. Первичное программное открытие, восстановление записи и обновление не создают повторной записи. При `C` сохраняются выбранный документ, вид, прокрутка и существующий набор вкладок; отсутствие выбранного документа после перечитывания является отказом, а не выбором другого документа.
